# POAR-G — Journey Content Matrix

| Journey | Terminology/state/ownership audit | Missing transition content | Target handoff sentence pattern |
|---|---|---|---|
| J01 Onboarding → goal | Saved state exists; generic `Continue` dominates | What was saved, expiry, next authenticated destination | “Your goal is saved for 72 hours. Create/sign in to continue with …” |
| J02 Review | Collection/submitted/under-review/published labels not always persistent | Submission owner and publication expectation | “Submitted to your consultant. You can still …; we’ll notify you when published.” |
| J03 Credit Center | Published truth strong; meaning secondary | Review publication → action transition | “Your Review is published. Start with [finding/action] in your Plan.” |
| J04 Plan/Nurture | Blocked/completed labels exist; owner and unlocked consequence vary | Completion → verification/readiness | “Completed. Your consultant now needs to verify … before …” |
| J05 Cards | Portfolio/research/Wishlist/Strategy terms can blur | Saved card → governed Strategy boundary | “Saved for research only. It is not part of an approved Strategy.” |
| J06 Services/payment | Processor language leaks; entitlement handoff uneven | Pending/verified/failed/refunded consequence | “[Payment state]. [Access/credit] remains [state]. Next …” |
| J07 Cycle/Round prep | Goal snapshot is explained; stage naming varies | Readiness/preparation owner | “Preparation is complete; your consultant can now prepare Strategy.” |
| J08 Strategy | Child page is clear; overview contradicts it | Canonical overview → approved Strategy | “Strategy vN was approved on … Review it, then …” |
| J09 Scheduling | Booking is clear; sync/revalidation technical | Strategy → eligible booking and booked → prepare | “You’re booked for … Prepare …; material changes may require review.” |
| J10 Live | One-card rule exists; presence/reconnect consequence unclear | Release → result → next card/pause | “Result recorded. Your consultant will review it before releasing another card.” |
| J11 Post-Round | Facts/advice separation strong; empty ownership weak | Live end → follow-up → analysis → finalization | “Session ended. Resolve N outcomes; then your consultant can publish Analysis.” |
| J12 Major Readiness | Non-lender-approval boundary strong | Restriction propagation and reassessment | “Card activity is [condition] because …; [owner] can reassess after …” |
| J13 Support | Visibility labels strong on staff side | Context attached and response expectation | “We attached [safe context]. Describe …; your consultant/support team owns next response.” |
| J14 Notifications | Subjects generally meaningful | Notification → destination and read state | “[Change]. [Why]. Review [named object].” |
| J15 Documents | Security/requirements clear | Upload → validation/Review usage | “Uploaded. It is available to [authorized role] and [next validation/use].” |
| J16 Account/session/MFA | Safety strong; interruption/return underexplained | Reauth/MFA → exact return | “Verify to return to [destination]. Saved/submitted work is unchanged.” |
| J17 Consultant daily loop | Routes connect; owning job is reconstructed | Dashboard/queue → client/workbench | “Open [work type] for [client] because [reason].” |
| J18 Admin identity/access | Objects/actions exist | Preview → step-up → result → audit | “This grants/revokes …; active sessions …; audit event …” |
| J19 Admin commerce | Provider-neutral domain is real | Action → financial/provider consequence | “Refund X via original provider Y; entitlement becomes Z; duplicate retry has no second effect.” |
| J20 Catalog/Insight | Draft/current/approval available | Approved Insight → client/consultant availability | “Approved vN is now available to …; prior version remains historical.” |
| J21 AI/source/rules/jobs | Config/execution boundaries vary | Configuration → effective execution | “Draft saved; no work changes until … / Effective for new jobs from …” |
| J22 Notifications/integrations | Provider/status operational | Disable/retry → delivery impact | “New deliveries stop/route …; in-flight …; restore by …” |
| J23 Retention/privacy | Governance exists | Request/preview/execution states | “Preview found N eligible; exclusions …; execution is irreversible; audit remains.” |
| J24 Security incident | Immutable events exist | Detection → containment → verification | “Observed …; affected scope …; action …; verify …” |
| J25 Stale/revalidation | Version/freshness domains exist | Source change → owner/review/unlock | “Changed after [event]. [Owner] must review before [capability].” |
| J26 Revocation/realtime | Server enforcement is strong | Permission loss → draft safety/destination | “Access changed. Unsaved work [state]. Return to … or contact …” |
| J27 Overview/deep-link truth | Newly identified | Overview contradicts valid children | Same canonical stage/owner/action string source across all projections |
| J28 Interrupted collection work | URL persistence inconsistent | Return after drawer/reauth | “Returned to [view/filter]; selected record [state].” Usually conveyed unobtrusively. |
| J29 Cross-role handoff | Notifications/queues exist; ownership prose incomplete | Client→consultant→system transitions | “[Actor] completed X. [Next owner] now needs Y. You will be notified when Z.” |

## Journey content acceptance

A journey fails if each page is locally understandable but adjacent pages disagree about stage, object name, ownership or next action. Transition content must be generated from canonical domain state, not maintained as parallel screen-specific guesses.
