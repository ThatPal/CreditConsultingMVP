## Compatibility decisions to prove before retiring routes

- Review aliases currently render the same workspace. Choose one canonical URL in U3; preserve client/review IDs, authorization, bookmarked history and return context before redirecting the second.
- `/crm/sessions` and `/crm/live-sessions` currently render the same collection. Canonicalize in U6 without dropping persistent Live awareness.
- Post-Round results/analysis/finalize are purposeful old deep links, not interchangeable aliases. In U7, map each to its corresponding workspace section, preserving Round/client identity.
- Provider detail paths under `integrations` must remain compatible when Commerce navigation is repaired in U7. Non-payment integration detail is still separate work.
- Embedded Client 360 sections and `support?case=` are implemented destinations. Counting only path declarations would incorrectly report five CRM screens as entirely missing.

## Audit instrumentation correction

The initial generator parsed JSX as text and selected the first capitalized element after removing `Suspense`. That selected `LoadingSkeleton` from the fallback attribute for three lazy routes. The parser now traverses rendered children only, records route props, guard context, index identity and redirect destinations, and rejects unsupported dynamic route syntax explicitly. The actual application remains 120 route declarations. Four focused parser tests cover this error and distinguish Admin audit/security variants. These are audit-tool tests, not product acceptance tests.
