## Queries, mutations and realtime

Current roots: `portal-home`, `portal-journey`, `published-credit-center`, `consultant-published-credit-center`, `client-plan`, plus Plan response/draft/history roots. Definitions are spread across pages and feature components.

`web/src/LiveUpdates.tsx` already maps publication/Plan domains to the actual collection roots (passes 42–44) and invalidates queries after a repeated connection opens. Keep recipient scoping, session-loss checks, stale-response protections and authoritative reconnect reads. Centralize key factories and mutation invalidation; do not replace those protections with optimistic event-only truth. `PlanResponse.tsx` currently invalidates client-plan/Home/Journey ad hoc; frozen Center's new Plan summary must participate too.

## Required compatibility contracts before U1 code

1. Legacy Journey/Cycle/Nurture → read-only source context. No new persisted focus lifecycle. Remove U4/U6 with explicit tests for no-active-work, stale sources, waiting, blockers and historical records.
2. Legacy published Review/CreditSnapshot → current/historical role-safe Profile/Analysis/Recommendation summary. Remove U3. Fail closed on missing approved fields; preserve source/publication dates.
3. Legacy Plan/Version/Item/Dependency/Path → final Plan read DTO. Remove U4. Preserve private draft recovery and immutable response history; path rows do not become new canonical API concepts.

These are required boundaries, not implemented adapters. No adapter was introduced in U0.

## Tests that must survive recomposition

Dirty/busy Plan refresh protection; private draft identity/version fencing; accepted-write versus failed-read recovery; history/evidence authorization; client submission distinct from consultant verification; source-review pauses; concurrent approval/reconciliation; account/session fencing; no automatic consequential mutation on reconnect or login. Existing passes 01–59 supply regression evidence, not permission to preserve conflicting business contracts.
