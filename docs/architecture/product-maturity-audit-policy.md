# Product maturity audit cadence

Run a maturity audit approximately every three product phases and at any major release, authorization, data-migration, or navigation gate. Each audit must:

- classify every mounted user route as accepted real, safe foundation, or future-owned preview;
- test the cross-cutting journeys that ordinary feature sprints can miss;
- remove fabricated facts, dead primary actions, and misleading readiness claims;
- re-audit the previously accepted high-risk surfaces and record regressions explicitly;
- leave later roadmap modules with their documented owner rather than implementing them early;
- publish a completion report containing evidence, unresolved risks, CI, and manual review instructions.

The next audit should be scheduled after the next three implemented phases or sooner if Phase 4 changes authentication, authorization, navigation, or retained data controls materially.
